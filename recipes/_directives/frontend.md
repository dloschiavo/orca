You enumerate every guideline below and affirmatively mark each one — even if the answer is "N/A because this feature has no tables". The value of a QA pass is that nothing is silently skipped; the moment you start omitting rules "because they're obviously not relevant", you will miss a real violation sitting right next to an obviously-irrelevant one.

The rules below are mined from real production bugs that shipped because someone eyeballed the feature and decided "looks fine". Every bullet exists because it *already broke something*. Treat the list as load-bearing history, not a style guide.

- **[Real Links for Navigation]** Any click that takes the user to a **whole new page/route** MUST be a real link that renders an `<a href>` on web — NEVER a programmatic `router.push/navigate/replace` (or `window.location`) fired from a bare `onPress`/`onClick` with no href. Programmatic-only navigation hides the destination on hover and breaks cmd/ctrl/middle-click "open in new tab" — fatal for the inherently multi-tab workflows these apps have. This is the rule for nav links, list/table rows that open a detail page, cards, breadcrumbs, "back to list" buttons, nav/menu/drawer items, logo→home, and marketing CTAs that go to a page. Audit EVERY `router.push`/`router.navigate`/`window.location` site under this rule — it is violated near-universally by default.
- **[Outlinks Open New Tab]** A link to a **different domain** (any external/outbound URL — not a same-origin app route) MUST open in a new tab and NEVER replace the current tab. On web that means `<a href target="_blank" rel="noopener noreferrer">` (and any programmatic open uses `window.open(url, '_blank')`, never `window.location.href = url`). The current tab is the user's place in our app; outlinking in-place destroys it and loses their state. This is distinct from [Real Links for Navigation] (which governs same-app route clicks); here the destination is off-domain, so new-tab is mandatory regardless of click modifiers. Audit every outbound `<a>`, expo-router `<Link>`, `Linking.openURL`, and `window.location`/`window.open` site: same-origin → in-place soft-nav is fine; cross-origin → new tab, always. **The expo-router `<Link asChild target="_blank">` trap (this is how it shipped broken once):** expo-router forwards `target`/`rel` to react-native-web's anchor ONLY via the special `hrefAttrs` prop, which it builds ONLY on the **non-`asChild`** path. Under `asChild` it spreads `target`/`rel` as plain props onto the cloned child (`<Text>`/`Pressable`), which RNW silently drops — so the rendered `<a>` has `target=null` even though the source clearly says `target="_blank"`. For any EXTERNAL `<Link>`, do NOT use `asChild`: render `<Link href={url} target="_blank" rel="noopener noreferrer" style={…}>{label}</Link>` so Link emits its own anchor with the attributes. **Verify in the rendered DOM, never from source:** `target="_blank"` written in JSX is NOT proof — load the page and read the actual `<a>` (`document.querySelectorAll('a')` → check `.target`/`.rel`); a green grep is exactly what hid this bug. The shared soft-nav click helper (`navClick`/`spaLinkClick`-style) must also guard external hrefs — an absolute/cross-origin/`mailto:`/`tel:`/`//host` URL is forced to a new tab and never handed to the SPA router.

No custom `TouchableOpacity`/`Pressable` dropdown implementations unless native `<select>` literally cannot work (multi-select with checkboxes, rich content in options). Flag any new custom-built selector that a native select would serve better.

Human-readable prose — prompt templates, review drafts, notes, descriptions, natural-language content, ASINs and other IDs — uses the default proportional font. Flag every `fontFamily: 'monospace' | 'Courier'` and verify the content is genuinely code/data. Mono is NOT how you make numbers look "tabular" or "technical": count badges, page numbers, dates, year ranges, statute/citation references (`12 U.S.C. § 1`), short-hash digests shown in chrome, and `min`/`max` input placeholders all use the proportional font. Every such identifier renders through a human-readable label before it reaches the screen: a curated label map keyed by the slug (`qaCheckLabel`-style), with a humanise-the-slug fallback so an unmapped value still reads as words, never raw. The raw slug may live ONLY in non-visible affordances (test ids, `accessibilityLabel` extras, data attributes, logs) — never as the visible text, a heading, a filter chip, a badge, or a column header. This is a hard QA fail: a screen that shows `some_namespace.some_key` to a user does not pass. When you add a new enum/rule/status, you add its label in the SAME change — an identifier with no label mapping is incomplete work. Audit every place a typed union or enum value is interpolated into JSX text (`{x.check}`, `{status}`, `{f.type}`) under this rule.
- **[Ago Needs A Timestamp]** Any relative "X ago" stamp MUST also expose the ABSOLUTE, local-timezone-adjusted timestamp on hover. Relative time is the right thing to *show* — "3m ago" reads at a glance and `Sep 22, 2026, 3:04 PM` does not — but it is lossy in the one direction that matters: a reader who has to correlate a moment with a log line, an email, a filing deadline, or another person's screen cannot recover the instant from "2d ago", and an app that only ever shows the relative form forces them into the database or the dev tools to get it. So: glance gets the relative form, hover gets the fact. The tooltip text is the full local timestamp INCLUDING THE TIMEZONE NAME and seconds (`Mon, Sep 22, 2026, 3:04:19 PM EDT`) — a bare local time that doesn't say *which* local is the same ambiguity the tooltip exists to remove, and these stamps get compared against server logs. This covers EVERY surface that renders an ago-string: activity feeds, session/bookmark rails, chat and comment timestamps, "last run / last checked / refreshed" meta lines, signer status rows ("signed 2h ago"), webhook delivery logs, admin/ops dashboards. **Never hand-roll it per surface:** the ago formatter and the tooltip live in ONE shared module (docpost: `components/RelativeTime.tsx` — `<RelativeTime value={iso} />` when the stamp is the whole text, `useTimestampTitle(iso)` when it's one token inside a longer line). A new open-coded `${m}m ago` ladder in a screen file is a fail on its own, tooltip or not. **RN-Web trap:** a `title` prop on `Text`/`View`/`TouchableOpacity` is SILENTLY DROPPED (react-native-web forwards only `dataSet`/`dir`/`id`/`tabIndex`/`testID`/`aria-*`) — it compiles, reads correctly in source, and never reaches the DOM. Set the attribute on the host node via a ref, and **verify in the rendered DOM** (`document.querySelectorAll('[title]')`), never from source. Where a duration is displayed with no underlying instant available ("checked 5m ago" computed from an age-in-ms), plumb the real timestamp through rather than shipping an ago-string with nothing behind it.

Z-index alone does NOT fix overflow clipping; they are different problems. Use `z-index: 9999` (Tailwind: `z-[9999]`). A `useRef` on the trigger + bounding rect on open is the canonical pattern. Verify the menu is not clipped in any overflow container before marking PASS.

NEVER hand-assemble a badge (a `View`+`Text` pill with bespoke padding/radius/weight/letter-spacing) or a button (a `TouchableOpacity`/`Pressable`+`Text` styled as a button) — open-coding these is *exactly* how the app drifted into ~28 divergent badge styles and buttons at mixed weights (some 600, some 700, "some bold and some not"). The components own the canonical spec (uppercase small-caps, `fontWeight 600`, `letterSpacing 1.2`, `borderRadius 2`); ONLY color varies, via `background`/`color`/`tone`/`variant`/`size` props. If a needed color, tone, size, or variant doesn't exist, ADD it to the shared component ONCE — never fork a one-off pill or button. The following are NOT badges/buttons — leave them on their own patterns: notification COUNT bubbles (small filled circular unread counts), filter chips, nav/list/detail rows (real `<a href>`), icon-only touchables, overlays/scrims, and selector triggers (native `<select>`). The test before writing any pill-shaped `View` or button-shaped `TouchableOpacity`: name the shared component you're using; if you can't, STOP and use it. A badge in a table row is wrapped in the shared badge cell (e.g. `s.cellBadge`) so it aligns to the row's text and its column header, not floating above/left.
- **[Button Label Language]** Button wording and casing are consistent app-wide — the shared `Button` enforces casing, you enforce wording. CASING: author the `title` in Title Case (`title="New Matter"`, `"Invite Member"`); the component renders it uppercase small-caps. NEVER pre-uppercase the string, add manual `letterSpacing`, or ship sentence-case / first-letter-only labels — casing consistency is automatic *because* every button flows through the component. WORDING — always name the object; never a bare verb or bare noun: create a fresh entity → `New {Object}` (`"New Workflow"`, `"New Matter"`); add an existing/simple item to a collection → `Add {Object}` (`"Add Domain"`); invite a person → `Invite {Object}` (`"Invite Member"`). FORBIDDEN: bare `"New"` / `"+ New"` with no object, a bare object with no verb (`"+ Contract"`), and mixing verbs for the same operation (don't say "Create" on one screen and "New" on another) — pick ONE verb per operation type across the app. The leading "+" is NEVER a literal character typed into the label; it is an expo-vector-icons `plus` icon in the component's icon slot (per [Expo Vector Icons]) or omitted — default to no glyph.

Browser-native dialogs are garbage-tier UX. Reuse those styles; don't invent new ones. Flag every `alert(`/`confirm(`/`prompt(` / RN `Alert.alert(` reached from a web path.

Use `alignItems: 'flex-start'` (flex), `align-items: start` (grid), or `vertical-align: top` (HTML tables); never center/end/stretch. If a shared/global class causes it app-wide (e.g. a section-header class set to `align-items: end`), FIX THE GLOBAL CLASS — don't sprinkle per-instance overrides.

- **[State Filtered Tabs]** Long mixed-state lists in dashboards/reports are split into tabs by state, with the most actionable tab as the default. Time-sensitive summary cards (e.g. "Today's Deliveries") sit above the tabs.
- **[Controls Co-location]** Search, filter, and compliance-indicator controls are co-located with the view's title/header in the card header's action slot — not isolated in a full-width row below navigation.

- **[Error Page Rules]** Design-system rules apply to error pages, 404s (`+not-found.tsx`), loading states, and empty states — not just the routes in the sidebar. Include them in the audit explicitly.
- **[Multi-Property Fix]** When a bug fix addresses multiple properties of the same element (color, background, border, icon), verify *every* property was fixed, not just the ones named in the commit.
- **[Full-Row Click Targets]** A row's tap/press handler covers the entire row — full height AND width — via padding on the `TouchableOpacity`/`Pressable` itself, not vertical padding on an outer non-clickable `View` and not the text's intrinsic size. Put `paddingVertical` on the touchable, let it `flex: 1`, and set the row container `alignItems: 'stretch'` so the touchable fills the row height. Symptom to avoid: only the text portion of the row is clickable. **The padding-on-the-wrong-element trap (recurring failure):** if a clickable row/header lives inside a parent that owns the padding (e.g. a `card` with `padding: N` wrapping a header `Pressable`), that padding ring is OUTSIDE the press target — the block *looks* bigger than it clicks, and clicks near the edges/the trailing count do nothing. The press target MUST own its own padding and be full-bleed to the container edges: strip horizontal/edge padding from the container (`padding: 0`) and move it onto the `Pressable` (`paddingHorizontal`/`paddingVertical`), or pull the `Pressable` out with negative margin equal to the container padding. Same rule for any "whole thing looks tappable" surface: collapsible section headers, list/table rows, cards, menu items, accordion bars. **Mandatory live verification before marking done:** the press target's bounding box must equal the visible block's box (measure both with `getBoundingClientRect`; left/right/top/bottom deltas ≤ the border width), AND a click in a non-text corner (e.g. over the trailing count, or the empty padding zone) must fire the handler. Eyeballing is not verification — measure the hit box.
- **[Padded Selection Backgrounds]** Any element that paints a background tied to state — selected/active/hover/pulsed rows, highlighted list items, chips, the active nav item, filter pills — MUST have horizontal (and vertical) padding *inside* that background so text never butts against the fill edge. The background edge sitting flush on the glyphs reads as broken every time. Recurring failure mode: a row that relies on an ancestor's padding for its text inset but paints its OWN selected `backgroundColor` — the fill then spans the row's content box with zero internal padding and the text touches both edges. Fix: put the horizontal padding on the SAME element that paints the background (`paddingHorizontal` on the `Pressable`/row itself), not on a parent. To keep a selection full-bleed to a padded card while still padding the text, give the row its own `paddingHorizontal` AND bleed it out with negative margin (or zero the card's padding and let the row own it), with `overflow: 'hidden'` on the card so the fill clips to the rounded corners. **Mandatory live verification:** select the element and confirm the gap between the background's left/right edge and the text is ≥ ~8px on BOTH sides (`textRect.left - rowRect.left` and `rowRect.right - textRect.right`); a faint, barely-visible selection fill counts as a fail too — the selected state must be clearly distinguishable.
- **[Nested Indent via Padding]** A node's expanded body / description / detail block aligns under its parent's **label text**, not the container's left edge. Compute the indent (`depth*step + chevronWidth + gap`) and apply it with **padding** (wrap the block in a padded `View`), never `marginLeft`. Margin-instead-of-padding and mis-indented detail blocks read as slop.
- **[Reorder Renumbers]** Reordering uses a single drag handle (e.g. FontAwesome `arrows-alt-v`) with HTML5 drag-and-drop on web — not up/down buttons. On drop, **renumber the affected siblings `0..n`**; never swap two `order` values pairwise, which silently no-ops when `order` values are duplicated or garbled. Renumbering self-heals duplicate orders on every move.
- **[Generative-UI First]** On projects that render dynamic surfaces with generative / LLM-driven UI (OpenUI), favor generative rendering overwhelmingly for data-driven surfaces (grid skeletons, panels, right-rail tab bodies) over hand-built deterministic components — but keep two disciplines so it doesn't get slow or sloppy: (1) generate the layout/container **once per schema signature** and memoize it — never regenerate per paint, and never let individual cells/microprompts emit their own UI; cells receive **typed data** streamed into the generated structure. (2) Carve out deterministic implementations for **action-capable** surfaces (signature ceremonies, anything that mutates state) and **security/compliance** surfaces (auth, privacy, legal disclosures). Map to the surface's capability: render-only / reads-context → generative; action-capable → deterministic tooling.

- **[Loading Pattern]** One consistent loading pattern across all data-fetching views (skeleton, spinner, or shimmer — pick one). No infinite spinners. On fetch failure/timeout, show an error state.

## Tables

- **[Full Width Tables]** Default width for all tables is full width.
- **[Nowrap Table Headers]** Never wrap or truncate a table header.
- **[Nowrap Timestamps]** Date/time cells never wrap. A timestamp such as `5/29/2026, 6:00:48 PM` breaking onto two lines (date on one row, a stray `PM` on the next) looks broken. Any cell rendering a formatted date/time — table columns, audit/event logs, "created at"/"last delivery" rows, activity feeds — gets `numberOfLines={1}` plus `whiteSpace: 'nowrap'` (web) AND a column width wide enough to fit the full formatted value without ellipsis. Widen the column; do not let it wrap or clip.
- **[Table Column Widths]** Column widths minimize truncation/wrapping/overflow — desktop screen first, then mobile. Every column is declared as exactly one of two KINDS, and the row always spans the card's full width with **zero dead space at the right edge**:
  - **RIGID** (`width: N`) — content has a bounded widest value: a badge from a closed set, a formatted date, a byte count, a currency amount, a file extension, a count. Size it ONCE to `max(widest real value, its own header label + sort caret) + cell padding`, then never grow or shrink it. MEASURE both halves of that max, don't guess — a rigid column narrower than its own header ellipsizes the header, which is its own hard fail ([Nowrap Table Headers]).
  - **ELASTIC** (`minWidth: N` + a `flexGrow` weight) — content is unbounded free text: a name/title/filename, a party or tag list, a type, a person, a description. These are the ONLY columns that can truncate, and therefore these are the columns that RECEIVE the row's leftover width — split in proportion to their grow weights, weighted by how badly each truncates. The primary identifier column (the name/title you scan the table by) always takes the largest share.
  - **The failure this rule exists to stop:** hand-picking a fixed pixel width for every column. The identifier column then ellipsizes at 280px while 330px of empty space sits past the last column — the table both truncates its most important data AND looks broken. Do not "fix" that by padding the last column or by letting the trailing space ride: **if any cell in the table ellipsizes while there is unclaimed width in the row, the wrong columns are rigid.** That is the whole rule.
  - **One layout source for header and cells.** The header cell and the data cell derive their box from the SAME exported function over the SAME column def (`columnStyle(col)`-style) — never two inline copies of the sizing expression, which drift the moment one is edited. Any spacer one side adds (a group-mode indent, a checkbox gutter, a drag-handle column) must exist on BOTH sides or on neither; a spacer on the header alone shifts every label off its own data.
  - **Wider than the card ⇒ scroll, never clip.** A card with `overflow: hidden` silently swallows every column past its edge — including the trailing row-actions (`•••`) menu, which becomes unreachable with no scrollbar to hint at it. Put the header AND the rows inside ONE horizontal scroller so they scroll together and stay aligned, with its content floored at `Σ(minWidth | width) + actions column` and `width: '100%'` so it fills the card when there is surplus and scrolls only when there isn't.
  - **Verification is measurement, not eyeballing** — MANDATORY in the browser before marking done: (1) `Σ(column widths) === row width`, i.e. dead space is exactly 0; (2) no element has `scrollWidth > clientWidth` except inside an elastic column at the narrowest width tested; (3) every header cell has `scrollWidth === clientWidth`; (4) for every column, the header cell's `x` and `width` equal the data cell's `x` and `width`; (5) re-measure at several card widths down to ~380px and confirm the columns hold their floors and the table scrolls rather than starving a column. Report the numbers, not an impression.
- **[Table Alignment]** Numeric and currency values are right-aligned; text is left-aligned. Consistent across all tables.
- **[Dark Scrollbars]** In dark mode, every scrollable container has dark-mode scrollbar styling (`::-webkit-scrollbar`, `scrollbar-color`, `scrollbar-width`) derived from app tokens. Includes page body, textareas, modals, sidebars, overflow panels. Scroll every scrollable area and verify.

## Data Visualization

- **[Data Viz Tokens]** Chart/graph/map colors use color tokens when a matching token exists. Rule applies to *all* color assignments — including data-mapping objects, legend entries, and conditional color lookups, not just UI chrome.




- **[Body Guard]** Content scripts guard all `document.body` access — check for existence, defer to `DOMContentLoaded` if null. Applies to `appendChild`, `style`, direct body manipulation.



### React Lifecycle

- **[Effect Cleanup]** Every `useEffect` that creates a subscription, timer, or in-flight fetch returns a cleanup function. `cancelled` flags are only sufficient if the async code *actually checks them* — if the async work is in an external `useCallback`, the flag is invisible. Inline the async work, pass a signal/flag, or use `AbortController`. Verify every `cancelled` flag is referenced by the code that calls `setState`.
- **[Ref Timer Cleanup]** `useRef` debounce timers have a component-level unmount cleanup: `useEffect(() => () => { if (ref.current) clearTimeout(ref.current); }, [])`.
- **[Stale Fetch Guard]** Sequential fetches are guarded against race conditions. Use `AbortController` or a request-ID check before `setState` so only the latest fetch's result is applied.
- **[Input Focus Stability]** Never let URL/router writes or controlled-prop resyncs steal focus or cursor/selection from an input the user is actively typing in. For any input whose value is sourced from URL/route params or an external store the input also writes back to: (1) treat local state as authoritative *while focused* — gate the external→local sync (`useEffect(() => { if (!focusedRef.current) setText(value) }, [value])`) behind a `focusedRef` flipped by `onFocus`/`onBlur`; (2) use `router.replace` / `setParams`, never `router.push`, for filter/search/page state — these are tweaks, not navigation, and `push` risks a route remount; (3) debounce the *URL write*, never the local typing — keystrokes update local state immediately, the debounce only delays the round-trip to the store; (4) never reset local input state from the external value mid-typing, for any reason ("stale prop reconciliation" included). If the URL and the input disagree because the user is typing, the input wins until blur. Mandatory wherever a debounced `router.push` is wired from an input.
